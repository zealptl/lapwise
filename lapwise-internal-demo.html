07Analysis deep-dive — the two hardest endpoints

The hard math

GET /v1/analysis/driver-pace

One driver → a full pace profile over the last 12 race weekends. Fetches sessions, starting grids, laps, stints and results from OpenF1 — concurrently with asyncio — then computes:

Qpace · qualifying
Each grid slot scores 21 − position, recency-weighted with 0.85 decay, scaled to 0–100. Newer vs older half ±10% ⇒ IMPROVING / DECLINING trend. Sector deltas vs field best name the strongest sector.
Rpace · race — the clean-lap funnel
every race lap
− lap 1 & pit-out laps
− safety-car laps (> threshold × median)
tyre age 3–15 only → clean laps
Each clean lap is divided by the session median so wet Spa and dry Monza compare fairly. Rpace = median ratio; the same maths runs for every driver to place them on a percentile vs the field. Plus: avg positions gained when starting P10+.
GET /v1/analysis/constructor-pitstop

The constructor signal: pit crew speed → fantasy points. Fetches pit stops + driver rosters for every Race and Sprint, maps each stop to its team, drops outliers > 60s, then scores every stop on the F1 Fantasy brackets:

10

5

2

points per stop · +5 bonus for the fastest stop of the race
Per constructor it then reports fantasy points / race, fastest-stop rate, sub-2s rate, and a consistency score — 100 − stdev × 100 — because for a constructor pick, a crew that's always 2.3s beats one that swings 1.9–3.5s.

10Deployment — two pit crews

Two-stop strategy

cdk deploy
API stack — infra/
Build — Docker image from service/, pushed to ECR
Synth — CloudFormation template from TypeScript
Ship — Lambda + API Gateway + Cognito + logs, one stack, outputs the API URL
agentcore deploy
Agent stack — agent/
Package — CodeZip of the ADK app, separate CDK stack
Wire — gateway URL injected as env var, scoped IAM auto-generated
Isolate — deploys & rolls back independently; the API never notices
